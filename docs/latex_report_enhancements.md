# OsdagBridge LaTeX report enhancements

The report generator assembles raw LaTeX chapter strings from the design payload and compiles them with pdfLaTeX. The refactor addresses six presentation problems in the existing generator. The design engine, load combinations, utilization calculations, and material take-off calculations use the existing implementation.

## Implementation

| Problem | Changes |
|---|---|
| Missing headings on continuation pages | `tables.py` generates the first-page and continuation headers. Chapters 2–5 and 7 use the helper for tables with column headings. Captions occur once. Chapter 5 keeps multirow girder blocks together using starred row breaks and partial rules that prevent a page break inside each block. |
| Footer clearance, clipped placeholders, and repeated page numbering | `styles.py` reserves A4 header and footer space, bounds running headers, shares the page styles, and limits figure height while preserving aspect ratio. The cover, contents, executive summary, and chapters use the same page counter. `report_utils.py` and Chapters 1, 4, and 6 wrap long metadata and size placeholders to the available width. The executive summary has unique TOC anchors, and Chapter 8 closes its local table-formatting groups. |
| Combined live-load presentation | `chap3.py` lists only the selected standard and custom vehicle classes. It uses PyLaTeX longtables for vehicle selections, vehicle parameters, and footpath loads, with separate value and unit columns. The lane-based braking estimate is converted from the vehicle library’s force units. If the lane count is absent, IRC 6 Table 6 resolves it from carriageway width. Centrifugal force displays as unavailable because the current bridge inputs contain no horizontal curvature. The footpath table shows the configuration, width, loading mode, and intensity when present. Automatic mode uses the existing IRC 6 Clause 206.1 resolver, and custom mode prints the entered value with the unit displayed by the input dialog. |
| Utilization ratios presented only in tables | Chapter 5 builds the summary table and chart data from the same governing check rows. Girder checks use stored DCRs, deck checks use the existing demand and capacity results, and transverse checks use the stored member design results. Braced end diaphragms use their own results in the overall summary. Numeric zero is retained and unavailable values are omitted from the charts. Charts place UR on the vertical axis, show a horizontal red dashed UR = 1.0 line, and share a vertical scale across charts. Section 5.4 also uses the diaphragm’s own capacity results and explicitly identifies missing results. |
| Material quantities presented only in the Bill of Materials | `chap7.py` plots totals from the same keys used by the bill of materials. The structural-steel and reinforcement axes use MT and the concrete axis uses m³. Steel quantities use the separate bracing chord totals to avoid counting the same steel twice. The bill and chart now include estimated end-diaphragm tonnage. The design supplies section masses per metre, nominal member lengths, and piece counts across both supports. The estimate excludes connections and fabrication allowances. |
| Formatting spread across report code | `styles.py` owns the shared LaTeX preamble, colors, page geometry, typography, table spacing, and chart settings. `tables.py` owns repeat-header formatting. `charts.py` shares the bar chart renderer and uses the non-interactive Agg canvas without altering the desktop's Matplotlib backend. |

`report_generator.py` stages charts with the existing report images in the temporary compilation directory when figures are enabled. It runs pdfLaTeX twice for page totals and the table of contents. A failed pass returns the TeX path and no PDF result. Charts are embedded with PyLaTeX Figure. Temporary images are removed at the end of generation. The exported TeX references its image assets, which are required when recompiling it separately.

## Verification

- Ran the full repository test suite with `python -m pytest -q`. All 20 tests passed, including the five existing tests and the new report tests. The report tests cover repeated headers, class selection and escaping, automatic and custom footpath modes, absent or optional inputs, raw UR consistency, the threshold, chart files, empty data, and two pdfLaTeX report configurations.
- The comparison used a 20 m, 7.5 m carriageway highway bridge with four girders, zero skew, and a single-sided footpath. OsdagBridge generated the engineering input and output snapshot once. Both reports consumed that snapshot. The revised report used the same bridge configuration and now includes the actual bending moment, shear and displacement plots. Desktop CAD images remain placeholders.
- [Report_Before.pdf](reports/Report_Before.pdf) is the original generator's 51-page output from unmodified `dev` at `d74f56d`. That generator saves the PDF despite both pdfLaTeX runs returning exit code 1 on alignment errors. The supplied `OsdagReport 1.pdf` is a separate 43-page visual reference.
- [Report_After.pdf](reports/Report_After.pdf) passed both pdfLaTeX runs with no TeX errors or overfull-box messages. Visual inspection covered the cover and contents, load tables, Chapter 4 placeholders, Chapter 5 continuation pages, and all five charts. PDF text extraction checks the footer page sequence and confirms that ULS-01 through ULS-08 and SLS-01 through SLS-07 appear once each.
- The executive summary uses stored design outcomes. The governing girder fatigue failure appears consistently in the summary, table, and utilization chart.
- The bridge model did not return a numerical end-diaphragm capacity check for the comparison case. The PDF states this explicitly. A regression test verifies that supplied end-diaphragm results reach their detailed table and the Section 5.5 chart data.
- The custom footpath display uses the input dialog’s kN/mm² label. The automatic resolver returns kN/m².
